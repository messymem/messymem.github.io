MessyMem:
Learning-from-Doing Memory for Mobile Manipulation

Anuva Banwasi, William Muckelroy III, Priya Sundaresan, Linfeng Zhao, Jeannette Bohg, Cherie Ho
Stanford University
Conference on Robot Learning (CoRL) 2026
Paper arXiv soon Code soon Video soon

MessyMem is a persistent memory system for mobile manipulation. It maintains a 3D scene graph that is globally queryable & spatially grounded, updated through interactions, and fine-grained via linked keyframes — so the robot reuses what it has learned instead of re-exploring.

Abstract

Mobile manipulators deployed across many rooms and visits should improve with experience: after discovering that a cabinet is locked or finding an object in a drawer, the robot should reuse that knowledge rather than start each task from scratch. Yet today's robots often treat each task as new: compact scene representations omit interaction-derived knowledge, raw video histories are difficult to query, and VLM planners reason at inference time without persistently updating what the robot knows.

We present MessyMem, a persistent memory system that enables mobile manipulators to learn from experience and reuse that knowledge across future tasks. It maintains a spatially grounded 3D scene graph of objects and locations, augments it with properties and outcomes learned through interaction, and links visual observations for fine-grained recall. We evaluate MessyMem in simulation and on a real mobile manipulator. In a continuous 25-task simulation spanning over 3 hours, MessyMem achieves 80.0% task progress, outperforming the strongest ablation by 14.8 percentage points and the strongest external baseline by 28.9 points, while retrieving task-relevant evidence from thousands of stored keyframes and over an hour into the past.

Three Properties of Robot Memory

Memory for mobile manipulation has to do three things at once. Prior work delivers them separately; MessyMem combines all three in one persistent store.

1

Globally Queryable & Spatially Grounded

Queries must work across rooms, floors, and sessions, in a form compact enough to actually search. Each query returns not only what the robot has seen but where to go to find it, so the planner can pick a visit order and navigate directly instead of re-exploring.

2

Updatable from Interactions

Weight, emptiness, articulation, locked-vs-unlocked — many properties cannot be inferred from passive observation and must be learned by acting. Memory has to record what each interaction reveals, including why an attempt failed.

3

Fine-Grained

Text summaries alone are often insufficient. The robot must retrieve visual context on demand — the exact shelf where coffee was last seen, the name printed on a particular cup, how cluttered one cabinet is compared to another.

Method Overview

The robot incrementally builds memory from RGB-D observations and manipulation outcomes. Execution runs in a closed loop: retrieve task-relevant memory, plan and execute a primitive, analyze its outcome, update memory, and replan against the updated state.

  2. 2Plannext primitive
  3. 3Executeon the robot

Scene Graph Builder

Each RGB-D frame is passed to SAM3 with a scenario-specific set of category prompts. Every mask is deprojected to 3D using the depth image, and same-label detections at nearby positions are clustered and associated with existing entries, whose centroids update as a running average. Unmatched detections initialize new nodes.

Each entry stores an object id (e.g. drawer_3), a 3D centroid for spatial grounding, and a property dictionary. Objects persist after leaving the camera view, so remembered state and visual evidence stay anchored to locations the planner can revisit.

Interaction Analyzer

After each manipulation primitive, a VLM converts the interaction window into structured updates to the targeted node. It reasons over a multi-frame collage rather than a single before/after pair, which exposes how the action unfolded — whether the gripper missed a handle, slipped during a pull, or grasped firmly while the cabinet stayed shut.

It maintains a seeded property vocabulary (accessible, pickable, pushable, fullness, openable), can add open-vocabulary properties when useful, records execution outcomes and failure reasons, and refreshes fixture contents. Newer evidence overwrites stale structured values, so incorrect memory can be corrected.

Keyframe Saver

A bank of selected RGB observations, each linked to the scene-graph entries it describes. Around every manipulation the system stores the frame before, the frame after, and the frame the analyzer flags as most informative. Outside manipulation, frames are saved whenever the graph registers a new object or updates an existing one.

Each keyframe keeps a full-resolution image plus a thumbnail, with metadata for timestamp, camera, trigger, originating action, robot pose, and linked nodes. Analyzer-written labels (e.g. open drawer interior) give retrieval cues for contents that have no scene-graph object of their own. Blank, blurry and near-duplicate frames are filtered out.

Memory Retriever & VLM Planner

The retriever pools candidates from three sources: keyframes linked to scene-graph entries, keyframes whose analyzer labels match content in the task, and recent interaction frames for short-term context. Per-source caps stop recently seen entities from flooding the pool.

Retrieval then runs in two stages. A text-only pass gives the VLM a compact catalog of candidate metadata and the scene-graph summary, and it shortlists frames likely to help. A multimodal pass then inspects thumbnails of that shortlist and picks a small, non-redundant set. Structured memory narrows the field first; visual reasoning is spent only on the finalists.

Experimental Setup

Every method shares the same planner, perception stack, and action primitives, so differences come from the memory representation alone.

Initialization

Each trial starts with a predefined trajectory that observes fixture locations without revealing their contents. Contents become observable only after interaction.

Task Sequence

Instructions are issued one at a time, each after the previous completes or fails — so information gathered earlier has to persist across decisions.

Primitives

All methods use identical navigation, fixture-interaction and manipulation primitives, with a fixed budget of twelve planner calls per simulated task.

Metrics

Task progress from task-specific success criteria, plus the number of actions used. Short scenarios run 50 trials per method, reported with 95% confidence intervals.

Compared Methods

Three ablations strip one memory component at a time; three external baselines represent alternative memory paradigms.

Ours & ablations
  • MessyMem (SG + IA + KF) — the full system: persistent scene graph, interaction-analyzer updates, and linked keyframes.
  • SG + IA — no keyframes. Tests whether structured, interaction-derived state suffices without visual history.
  • SG + KF — no interaction analyzer. Keeps positions and keyframes but stores nothing learned from acting.
  • SG — labels and positions only. The limit of a queryable spatial representation on its own.
External baselines
  • RoboEXP — its Action-Conditioned Scene Graph adapted to our execution stack: predefined relational structure, no fine-grained appearance.
  • MemER-style — episodic visual memory, where a VLM selects salient observations clustered into representative keyframes, without persistent scene-graph indexing.
  • MemER + Fixtures — the same, additionally given identities and positions of visible and out-of-view fixtures, to separate episodic-memory limits from basic navigation grounding.

Simulation

Scenarios are built in the MuJoCo-based RoboCasa365 simulator for household mobile manipulation. The simulated robot is a Franka Panda arm on an Omron mobile base; RGB-D observations come from third-person cameras for scene-graph construction, with the wrist camera feeding interaction analysis and keyframes.

Locked-and-Unlocked Cabinets

Globally queryable Updatable from interactions

Among three cabinets, one is locked — but its status is unknown before interaction. The robot is first told “look into the upper cabinets and find the banana”; its first attempt on cab_1 fails because that cabinet is locked, and it finds the banana in cab_2. Asked next to find the ketchup, success requires skipping both the locked cabinet and the ketchup-free one, and navigating to the still-unexplored cab_3. Re-attempting the locked cabinet counts as a failure.

Clutter-Aware Pick

Globally queryable Updatable from interactions Fine-grained

Two cabinets both contain a ketchup bottle. In one it sits alone with clear side access; in the other it is wedged between tightly-clustered items. Crucially the cluttered cabinet holds fewer items overall, so raw object counts are anti-correlated with accessibility. After finding the mustard seeds memory with interior keyframes, the robot is asked to pick up the ketchup — ending up in front of the wrong, already-open cabinet. Choosing correctly means comparing the two interiors from stored keyframes, not counting labels.

Long Horizon — 25 tasks, 3+ hours

Globally queryable Updatable from interactions Fine-grained

A continuous sequence of 25 household tasks in a 10-cabinet kitchen holding more than 60 objects and fixtures, executed for over three hours without resetting memory. This is the scenario where all three memory properties are exercised jointly: tasks require recalling observations from much earlier in the run, distinguishing visually similar instances, reasoning about where household objects belong, and reusing what prior manipulation revealed.

The sequence spans four task families, each stressing a different part of memory:

Family 01

Finding

Locate an object whose position was revealed only earlier in the run. Success depends on the scene graph still holding where it was seen, hours and dozens of actions later, so the robot navigates straight there instead of re-searching the kitchen.

Example finding a mug that was put away earlier

Family 02

Matching

Pick out one instance among visually similar variants, where the distinguishing detail is appearance rather than category. A structured label like cup cannot separate them — only a retrieved keyframe can.

Example matching a cup to one observed earlier; identifying a reusable bottle among similar variants

Family 03

Manipulation

More than recalling where an object belongs, this is reasoning about whether an action will actually work. The interaction analyzer's property vocabulary is what carries that judgement forward:

openablefullnessaccessiblepickablepushable

A fixture recorded as locked or stuck is ruled out before the robot drives to it; fullness and accessible say whether there is room and a clear approach; pickable records what has genuinely been lifted before rather than what merely looks liftable.

Object counts alone mislead. A cabinet holding fewer items can be the harder one to pick from when the target is wedged behind them — so a planner reasoning only over the scene graph's tallies drives to exactly the wrong cabinet. Executability comes from what the analyzer wrote down and what the keyframes show, not from how many labels a node happens to list.

Example putting an object away with the items it belongs alongside; choosing the reachable instance over a nearer one that is boxed in, and skipping a fixture already known to be locked

Family 04

Memory Queries

Answer a question directly from memory, with no physical action at all. The task is satisfied only when the answer is recovered from stored state, which makes these the purest test of whether the memory is genuinely queryable.

Example recalling which objects were stored in the cabinet with the ketchup and mayonaise

Fine-grained memory enables instance-level reasoning

On Cluttered Pick, MessyMem reaches 84% against 58% for SG + IA and 51% for SG + KF. Without keyframes the robot remembers where ketchup was seen but cannot recover the visual arrangement needed to choose the less obstructed instance.

Interaction-derived memory captures outcomes

On Locked / Unlocked, MessyMem reaches 99% and SG + IA 88%, against 43% for SG + KF. A saved image alone cannot distinguish a locked cabinet from a failed grasp; the analyzer reasons over the whole manipulation to tell them apart.

External memory systems fall short

RoboEXP's predefined Action-Conditioned Scene Graph captures spatial structure but not fine-grained appearance or richer interaction-derived state. MemER-style memory struggles in mobile manipulation, where fixtures leave view and keyframes lack persistent spatial grounding — supplying fixture positions lifts it from 0% only to 8% and 27%.

Memory Remains Useful as It Grows

Over three hours of continuous operation, the current goal and scene-graph associations narrow thousands of observations to a small candidate set before visual reranking — so task-relevant experience stays reachable even as visual memory grows.

9,669 median keyframes accumulated
8.6s median retrieval latency
62.7min median lookback into the past

All six paired comparisons on the long-horizon evaluation remain significant after Holm correction (pHolm < 10−4). Over 3+ hours, MemER's recency bias makes older evidence increasingly hard to surface, while MessyMem retrieves against the current goal and its scene-graph associations. RoboEXP's limitation is instance-level: remembering that a cereal box is inside a cabinet does not distinguish Froot Loops from a visually similar Trix box.

Real Robot Results

The simulation findings transfer to hardware: MessyMem reaches 1.00 task progress in both real-world scenarios, while each ablation exposes a distinct failure mode under real perception and manipulation variability.

Platform

A TidyBot++ with a 6-DoF YAM arm and holonomic mobile base. Two ZED 2 RGB-D cameras support scene-graph construction and 3D localization — a front-facing base camera and a pole-mounted camera giving a higher vantage point to the VLM planner. A wrist-mounted Arducam fisheye adds views for keyframe memory, and wall-mounted fiducial markers support localization. Manipulation skills are dynamic movement primitives fit from a handful of teleoperated demonstrations, retargeted to each object by a VLM 3D-pointing module.

Office Drawer Search

Globally queryable Updatable from interactions Fine-grained

Three office drawer units: the left is locked, the middle and right unlocked. Scissors sit in the right drawer, a banana in the middle, and an orange cup labelled “John” on top of the locked left unit. The robot receives three sequential instructions — “Find me scissors”, then “Move to John's cup”, then “my friend just placed a gaming controller into one of the unlocked drawers, help me find it”. Across them it must remember which drawer failed to open, what contents it already observed, and which locations remain plausible.

MessyMem is the only method to complete all three goals, at 1.00 overall progress in 10.8 steps. Reusing the discovered lock status rather than retrying an infeasible interaction finishes the first goal in 6.4 steps against 7.4 for SG + KF and 9.4 for SG. The second goal needs fine-grained detail absent from the scene graph: MessyMem reaches 1.00 where SG + IA reaches 0.60.

Sock Pairing

Globally queryable Updatable from interactions Fine-grained

Two sock-filled drawers and one unpaired sock on a chair. The robot inspects both drawers, then places the loose sock into the drawer holding its match. Because candidates can share coarse attributes like colour, success depends on recalling fine-grained appearance — pattern as well as colour — while keeping the spatial association between that visual memory and its drawer. The distinguishing attribute and matching drawer are randomized between trials, so the answer cannot be memorized.

Limitations & Future Work

  • Closed-set detection. The current implementation uses a predefined closed-set prompt for object detection. Incorporating open-vocabulary detectors would let memory capture more diverse objects and attributes.
  • Robot-initiated actions only. The interaction analyzer reasons about the robot's own actions. Extending it to human actions would broaden the framework to HRI settings, where memory must update from both robot and human activity.
  • Richer primitives. The same memory-conditioned interface could be extended to more expressive policy primitives, including VLA-based policies.
